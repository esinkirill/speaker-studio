# Как повторить расчёт ШИМ

Здесь находятся два независимых опыта: математическая модель PWM и короткая
проверка расписания потока Windows. Они помогают понять, как заполнение,
округление ширины и задержки влияют на сигнал. Объяснение результатов —
в [разборе ШИМ и PC speaker](../../docs/PWM.md).

## Математическая модель

Для `pwm_model.py` нужен Python с NumPy и ReportLab из
[requirements.txt](requirements.txt). При исходном расчёте использовался
Python 3.12.14. Эти зависимости относятся к исследованию; Python runtime
приложения Speaker Studio менять для него не требуется.

Из этой папки выполните:

```powershell
python .\pwm_model.py
```

Скрипт создаёт графики SVG и PDF в `figures/`, численные результаты
`results/pwm-model-results.json` и таблицу `results/synthetic-jitter-metrics.csv`.
PNG появляются только при передаче необязательного аргумента
`--pdftoppm` с путём к уже имеющемуся `pdftoppm.exe` из Poppler.
Для расчёта и SVG/PDF Poppler не нужен.

Модель использует несущую 20 кГц, тон 500 Гц, заполнение
`0,5 + 0,45 × sin(...)` и 100 мс сигнала. Спектр вычисляется из точного
интеграла импульсов; идеальный фильтр сохраняет частоты до 2 кГц.
Также сравниваются смесь 440/660 Гц, округление ширин до такта PIT
`1 193 182 Гц` и выбранные независимые Gaussian ошибки ширины с seed 29.

Центры кадров остаются точными. Реальные пропуски кадров, I/O, излучатель,
напряжение и акустика в модель не входят. Фильтр использует и прошлые,
и будущие значения; это математический ориентир, а не схема реального speaker.
NRMSE описывает ошибку волны в заданной полосе и не является процентом
субъективного качества. Пример сохранённого вывода —
[model-results.json](model-results.json).

## Расписание потока Windows

`SchedulerProbe.cs` отмечает моменты выдачи условных отсчётов при активном
ожидании и `Thread.Sleep(1)`. Для периодов 50 и 1000 мкс каждый вариант
наблюдается одну секунду; опоздавшие слоты пропускаются без выдачи пачкой.
В измеряемом цикле нет обращений к портам, аудиоустройствам или InpOut.

В Windows с имеющимся .NET Framework 4.x можно собрать и запустить опыт
из этой папки в PowerShell:

```powershell
$probeCompiler = Join-Path $env:WINDIR 'Microsoft.NET\Framework64\v4.0.30319\csc.exe'
& $probeCompiler /nologo /target:exe /r:System.Web.Extensions.dll /out:SchedulerProbe.exe SchedulerProbe.cs
if ($LASTEXITCODE -eq 0) { .\SchedulerProbe.exe '.\scheduler-local.json' }
```

Проверка записывает JSON в переданный файл и выводит его в консоль.
[scheduler-observation.json](scheduler-observation.json) содержит исходное
короткое наблюдение на одном ПК. Новый запуск даст свои задержки: они зависят
от машины и нагрузки. Эти числа не измеряют время InpOut, сигнал на контактах
или звук и не задают максимальную возможную задержку Windows.
