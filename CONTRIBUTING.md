# Вклад в Speaker Studio

Основные направления: выделение основной мелодии, аккуратное управление временем,
совместимость аппаратного пути и удобство UI. Сначала найдите конкретный сценарий,
который улучшается изменением; новые зависимости нужны только для обоснованной задачи.

## Работа с кодом

1. Прочитайте README и [ARCHITECTURE.md](docs/ARCHITECTURE.md).
2. Соберите приложение: `.\speaker-player\build.ps1`.
3. Воспроизведите проблему на искусственном MIDI/CSV.
4. Измените нужный модуль, сохраняя совместимость C# 5 / .NET Framework 4.
5. Выполните `.\speaker-player\test.ps1` и укажите результат в pull request.

График, экспорт CSV и playback должны использовать одну и ту же преобразованную
последовательность. Изменения `SequenceTiming` проверяйте по общей длительности,
паузам и повторным атакам. Изменения seek проверяйте во время звука, тишины и pause.

## Описание аппаратного эксперимента

Укажите модель платы, обозначение разъёма по руководству, Windows version,
разрядность, версию InpOut и параметры сигнала. Разделите наблюдения:

- вызов программы выполнен;
- регистр прочитан или изменён;
- физический speaker действительно звучал;
- измерены частота и время переключения.

Если есть только первые два результата, звук ещё не подтверждён.
Не публикуйте IP, пароли, серийные номера и личные пути.

## Исследование распознавания мелодии

Для сравнения алгоритмов задайте общую аудиозапись с правом распространения,
ручную разметку нот, единый временной диапазон и критерии оценки.
Согласие двух алгоритмов — полезный контроль, но не ground truth.
Не загружайте чужие песни и веса моделей в pull request.

Для нового отчёта используйте [шаблон эксперимента](docs/EXPERIMENT_TEMPLATE.md).
